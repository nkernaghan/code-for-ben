# Curriculum Architect

Design cohesive educational programs with clear learning progressions, scaffolded complexity, hands-on labs, and student assessments. This skill covers curriculum mapping, prerequisite chains, lab design, and program evaluation.

## Curriculum Design Framework

### Phase 1: Goal Definition
- **Target audience:** Who are the students? (background, goals)
- **Outcomes:** What can they do after? (skills, projects)
- **Duration:** Weeks? Months? Full-time? Part-time?
- **Constraints:** Budget, instructor availability, technology access

### Phase 2: Content Mapping
```
Prerequisite Topics (Week 1-2)
    ↓
Foundation Topics (Week 3-4)
    ↓
Core Topics (Week 5-10)
    ↓
Advanced Topics (Week 11+)
    ↓
Capstone Project (Final 2 weeks)
```

### Phase 3: Learning Progression
- **Complexity curve:** Gentle ramp, then steeper (not all hard at once)
- **Reinforcement:** Revisit concepts in new contexts
- **Spaced repetition:** Review old concepts weekly
- **Active learning:** Don't just lecture; build it

### Phase 4: Assessment Strategy
- **Formative:** Daily quizzes, code reviews (guide learning)
- **Summative:** Exams, projects (measure mastery)
- **Peer review:** Students learn from each other
- **Capstone:** Cumulative project demonstrating all skills

## Pre-Program Course Structure

### Example: 5-Day Week 1 Course (AI/Crypto prep)

**Day 1: AI Foundations**
- Lesson: What is machine learning? (30 min)
- Lab: Train a simple classifier in Python (45 min)
- Reading: Chapters 1-2 of textbook
- Quiz: 5 MC questions on key concepts

**Day 2: Neural Networks & LLMs**
- Lesson: How transformers work (30 min)
- Lab: Fine-tune an LLM on custom data (45 min)
- Reading: Chapter 3
- Quiz: Conceptual questions on attention

**Day 3: Embeddings & RAG**
- Lesson: Vector embeddings (30 min)
- Lab: Build a RAG system (45 min)
- Reading: Chapter 4
- Quiz: Short answer on RAG architecture

**Day 4: APIs & Agents**
- Lesson: Building with Claude API (30 min)
- Lab: Build an agentic workflow (45 min)
- Reading: Chapter 5
- Quiz: Code review assignment

**Day 5: Capstone + Retrospective**
- Mini-project: Combine all topics (2 hours)
- Peer review: Students critique each other (30 min)
- Retrospective: What stuck? Questions? (30 min)
- Celebration: Demo projects, feedback

## Lab Design Principles

### 1. **Scaffolded Difficulty**
- Part A: Starter code + guide (boilerplate provided)
- Part B: More responsibility (fill in blanks)
- Part C: Independent challenge (build from scratch)

### 2. **Immediate Feedback**
- Auto-graded tests (pass/fail instant)
- Code review from instructor within 24 hours
- Peer feedback during lab

### 3. **Realistic Scope**
- Completable in 1 hour for strong students
- 2 hours for average students
- 3 hours for students needing more time

### 4. **Clear Success Criteria**
```
✓ Lab complete if:
  - Code runs without errors
  - Passes all test cases
  - Follows style guide
  - Includes comments for complex logic
```

### 5. **Build Toward Capstone**
- Each lab is a building block
- Final project reuses lab code
- Students see their work accumulate

## Prerequisite Chains

**Example: Solana Development Program**
```
Python Basics (Week 1)
    ↓
Crypto Fundamentals (Week 2)
    ↓
Blockchain Basics (Week 2-3)
    ↓
Solana Architecture (Week 3-4)
    ↓
Solana SDK & Web3.js (Week 4-5)
    ↓
Program Development (Week 5-7)
    ↓
Capstone: Build a complete dApp (Week 8)
```

**Each week assumes:**
- Knowledge from all previous weeks
- Comfort with reading/writing code
- Access to dev environment

## Assessment Types

### Formative (Daily)
- Code quizzes (write a function, does it work?)
- Concept checks (multiple choice on readings)
- Peer feedback on labs
- Office hours Q&A

### Summative (Weekly)
- Lab submission with auto-graded tests
- Small project combining week's topics
- Written reflection on learnings

### Capstone (End of program)
- Build a real project from scratch
- Present to peers & instructors
- Code review by senior developer
- Demo to potential employers/investors

## Reading Material Strategy

### Pre-Reading (Before class)
- 20-30 pages per week (not 200+)
- Focused reading guides (highlight key sections)
- Comprehension quiz before class (ensures reading)

### In-Class
- Lecture on readings (30-40 min)
- Interactive discussion (students ask questions)
- Lab demonstrates concepts (45-60 min)

### Post-Class
- Optional deeper reading for interested students
- Links to research papers, blog posts
- Encourage note-taking and reflection

## Student Support Structure

### Help Channels
- **Office hours:** 2-3 slots per week (instructor available)
- **Discord/Slack:** Peer-to-peer, instructors monitor
- **Email:** For private concerns
- **Pair programming:** Buddies for labs

### Early Intervention
- Track quiz scores & lab completion
- Flag students at 50% or below
- Outreach: "Let's talk about X. How can I help?"
- Offer extra tutoring or 1-on-1 time

### Accommodations
- Extended deadlines for documented disabilities
- Alternative labs (different programming language, etc.)
- Recorded lectures for async students
- Captioning for video content

## Evaluation & Iteration

### Weekly Reflection
- [ ] Did students grasp the concepts? (Based on quiz scores)
- [ ] Was the lab scope right? (Did they finish in time?)
- [ ] Was the pacing good? (Too fast, too slow, just right?)
- [ ] What questions came up most? (Adjust explanation)

### Mid-Program (Week 4-5)
- Anonymous survey: What's working? What's not?
- Adjust pace, labs, or delivery based on feedback
- Add optional deep-dives for advanced students

### Post-Program (Final)
- Final survey: Overall satisfaction, clarity, difficulty
- Track job placements, salaries, hiring partner feedback
- Measure: Did students achieve stated outcomes?

## Common Pitfalls

❌ **Assumes too much prior knowledge** — New students drop after week 1
❌ **Labs too hard without enough scaffolding** — Students copy/paste, don't learn
❌ **Reading assignments too long** — Students don't do them
❌ **No space for questions** — Students feel rushed
❌ **All lecture, no lab** — Passive learning = low retention
❌ **Capstone too ambitious** — Students feel defeated
❌ **No feedback mechanism** — You don't know what's broken

## Content Checklist Per Week

- [ ] Learning objectives clearly stated
- [ ] Prerequisite knowledge assumed (list it)
- [ ] Readings selected (20-30 pages)
- [ ] Lecture outline (30-40 min, interactive)
- [ ] Lab designed (scaffolded, completable in 1-3 hours)
- [ ] Test cases written (for auto-grading)
- [ ] Quiz/assessment prepared (formative or summative)
- [ ] Office hours scheduled
- [ ] Backup plan if students are struggling
- [ ] Capstone project hints (how does this week build toward it?)

## Success Metrics

- **Completion rate:** % of students finishing program
- **Mastery rate:** % passing assessments (target 80%+)
- **Satisfaction:** NPS or survey score (target 8+/10)
- **Outcomes:** Job placement, project showcase, community feedback
- **Retention:** Students applying skills after program ends
